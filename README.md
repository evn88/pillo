# Pillo

Локальное Expo-приложение для расписания приёма препаратов, учёта остатков и напоминаний. Приложение работает без аккаунта и не отправляет пользовательские данные на сервер.

## Платформы

- iOS/iPadOS 16.4 и новее: iPhone и iPad;
- Android 7 (API 24) и новее: телефоны и планшеты.

Интерфейс использует нативную нижнюю навигацию Expo Router; конкретное tablet/split-view поведение подлежит device-приёмке.

## Хранение и уведомления

- данные хранятся локально в `expo-sqlite` внутри sandbox приложения;
- Android backup/restore отключён (`android.allowBackup=false`). На iOS локальный native adapter помечает SQLite-файл и его WAL/SHM как исключённые из backup при открытии и после записи; перенос и restore всё ещё требуют проверки на физическом устройстве в development/release build;
- календарь рассчитывается на 35 дней вперёд, а `expo-notifications` получает не более 60 ближайших событий; фактическая дата покрытия показана в настройках, для продления требуется открывать приложение;
- на экране блокировки не показывается название препарата;
- очистка в настройках удаляет прикладные записи и локальный recovery-payload; это логическая очистка, а не обещание физического стирания файла;
- серверной синхронизации и авторизации нет.

## Разработка

```bash
npm ci
npm run ios
# или
npm run android
```

Для быстрой проверки чистой TypeScript-логики:

```bash
npm run type-check
npm test
npm run lint
npx expo install --check
```

Native debug/release build, требования к устройствам и порядок приёмки описаны в [матрице сборок](openspec/changes/harden-pillo-reliability-and-architecture/evidence/native-build-matrix.md). Локальные уведомления проверяйте на физическом устройстве: Expo Go не доказывает production-поведение разрешений и уведомлений.

Архитектура и текущее состояние работ: [передача следующего этапа](openspec/changes/harden-pillo-reliability-and-architecture/handoff.md).

Ранняя web-концепция сохранена отдельно как [исторический документ](pillo-mini-app-description.md) и не описывает текущую реализацию.
